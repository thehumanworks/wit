Refill the disk cache (cloud pack, else GitHub clone) or pin a memory snapshot

Usage: wit <cache|c> [OPTIONS] [REPO]

Arguments:
  [REPO]  Repository in "owner/repo" format (alternative to -r/--repo)

Options:
      --ignore <PATH|GLOB>     Exclude files, directories, or glob patterns (repeatable)
  -r, --repo <REPO>            Repository in "owner/repo" format
      --branch <BRANCH>        Branch name under refs/heads to cache instead of the repository default branch
      --backend <disk|memory>  Snapshot backend: disk (default; local bare-repo cache filled from the shared cloud pack cache, else a GitHub clone) or memory (GitHub API into RAM, no disk writes). Overrides WIT_SNAPSHOT_BACKEND
  -h, --help                   Print help

Disk backend (default): force-refresh the bare-repo cache for the repository default branch, or the selected branch when --branch is set. The refill resolves the branch commit with git ls-remote, downloads that commit's pack from the shared cloud cache (WIT_CACHE_URL; on by default in release builds) and verifies it locally, and falls back to a depth-1 GitHub clone. Memory backend: open the repo over the GitHub API into RAM (prefetch tree; no WIT_CACHE_DIR writes, no shared cloud cache).

Pass the repository as a positional `owner/repo` or with -r/--repo. If both are given they must match.

Repo-reading commands on disk normally serve cached content immediately and revalidate in the background. Pass --refresh-cache on tree, ls, cat, rg, sed, head, tail, or ast when a disk read must wait for a fresh cache.

Run wit --help for the cloud cache variables and how to disable it.

Examples:
  wit cache ratatui/ratatui
  wit cache -r ratatui/ratatui --branch main
  wit cache octocat/Hello-World --backend memory
